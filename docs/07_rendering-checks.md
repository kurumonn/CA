# Round 4 描画検証・一時停止中の負荷対策

## 適用した変更

学習画面は、一時停止してカメラも静止している間、同じWebGLフレームを連続して描画しません。再生、シーク、条件変更、カメラ操作、画面サイズ変更があると再描画します。非表示のタブでは教材の時間を進めません。

これは画質を下げる対策ではありません。分割GLB、PBRテクスチャ、影、条件別のカード内容は維持します。モデル単体ビューは別の描画ループであり、この最適化を適用したとは扱いません。

## CIで発生した問題

初回のAtlas CIでは、40 GLBの構造検査と9条件の内容検査を通過した後、モバイル寸法へ変更した場面のスクリーンショットが30秒でタイムアウトしました。基準コミットは `352a8c3`、実行番号は `37873383486` です。

静止中の連続描画を削減し、試験中は不要な自動カメラ遷移を使わないようにしました。ソフトウェア描画のスクリーンショット待機上限を120秒にしています。タイムアウト延長を実機性能の保証と解釈してはいけません。

## 検査条件

`viz/tests/atlas-render-check.mjs` は、通常のHTTP配信から実際のGLBをロードします。40モデルの存在、9条件の結果・カード内容・CRL発行者、秘密鍵の固定位置と材質分離、モバイル寸法、6モデルの埋込クリップを確認します。

追加した回帰検査では、一時停止してカメラが固定された状態の描画回数が1秒間増えないことを確認します。既存の意味内容のassertionは削除していません。これは性能改善の機能検査であり、FPS測定ではありません。

ローカル検査はChromium 144／SwiftShaderで実施しました。ローカルの通常HTTP遷移が制限されるため、ファイルのメモリ供給とURL条件の注入を使います。CIのHTTP検査とは分けて記録します。実GPUのFPS・VRAMは未測定です。

## 実行

リポジトリ直下のテスト環境で `python -m http.server 8765 --bind 127.0.0.1 --directory viz` を起動し、別ターミナルから次を実行します。目的は実HTTP経由の3D表示と内容検査です。

```bash
node viz/tests/atlas-render-check.mjs http://127.0.0.1:8765/ screenshots-atlas
```

正常例は `ATLAS OK: 40 GLBs, 15 scene/clip checks` と終了値0です。異常例はassertion失敗、読込失敗、スクリーンショット待機期限超過と非ゼロ終了です。終了値だけでなく、出力した画像・results.jsonも確認してください。事前に `cd viz && npm ci && npx playwright install chromium` で固定されたテスト依存を準備します。
